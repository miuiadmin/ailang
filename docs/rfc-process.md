# AILang RFC 流程（RFC Lifecycle）

> 本文档定义 AILang 设计提案（RFC，Request for Comments）的生命周期与采纳标准。规范 `docs/AILANG.md` §1.5 引用本文档作为规范性变更的治理通道。本文档随规范演进，非冻结决议。

**状态**：Draft（2026-07-27 引入，P0-0 治理地基）
**适用范围**：对 `docs/AILANG.md` 规范性内容（Part I 语言规范 §7–§27、§24、§1.5）的任何变更、新增特性、或对冻结决议（§83–§94）的重新讨论，**应**经 RFC。纯资料性修订（笔误、排版、附录扩充、遗留登记）无需 RFC。

## 1. 动机

v0.2.1 冻结前，设计决断以「决议记录」（§83–§94，记录 I–XII）形式沉淀，缺乏统一的「提案 → 评审 → 采纳」流程。本流程为后续演进（P0-1 至 P0-4、v0.3+）提供可追溯、可对抗验证的治理通道，确保：

- 每项变更在采纳前经多轮对抗式审查（见已有 RFC 0001–0004 的验证轨迹）；
- 冻结承诺不被静默破坏；
- 实现者与贡献者对「何为已采纳规范」有单一权威答案。

## 2. 状态机

一份 RFC 的生命周期：

```
Draft → Review → FCP（Final Comment Period）→ Accepted → Implemented
                        ↓                         ↓
                     Rejected              Postponed / Withdrawn
```

| 状态 | 含义 | 进入条件 |
|---|---|---|
| **Draft** | 作者起草中，未公开征求 | 新建文件 `docs/rfc/NNNN-title.md` |
| **Review** | 公开征求意见与对抗式 workflow 审查 | 作者自评完成、结构齐备 |
| **FCP** | 最终评论期，无新分歧则进入采纳 | 至少一轮 workflow 收敛至 0H/0M/0L，或 shepherd 裁定剩余项均为非缺陷 |
| **Accepted** | 采纳为规范一部分，待实现 | FCP 期满无阻断性异议 |
| **Implemented** | 已落地到 `docs/AILANG.md` 正文或编译器 | 合并到规范 / 编译器对应 Phase |
| **Rejected** | 明确否决 | 评审裁定不采纳 |
| **Postponed** | 暂缓（如依赖未就绪的 P0 前置） | 标注阻塞项与重开条件 |
| **Withdrawn** | 作者撤回 | 作者主动撤回 |

## 3. 编号与文件

- 编号：连续四位数字 `NNNN`，从 `0001` 起。
- 路径：`docs/rfc/NNNN-kebab-title.md`。
- 已有：`0001` doctest、`0002` contracts、`0003` pbt-fuzzer、`0004` smt-sidecar（均 Draft，v0.3+）。
- 每份 RFC 头部**必须**含：标题、状态、版本（Draft vN）、关联 P0/P1 分级、是否触动冻结规范、是否新增关键字 / 文法产生式。

## 4. 采纳标准

一份 RFC **应**在以下全部满足后方可进入 FCP：

1. **自洽**：与 `docs/AILANG.md` 既有规范（尤其 §1.5 治理层、§17 错误模型、§90 数值 / 逃生舱）无矛盾；
2. **可对抗验证**：经至少一轮多维度 workflow 审查，收敛至 0 HIGH / 0 MEDIUM / 0 LOW，或对未收敛项给出可辩护的保留理由；
3. **冻结影响声明**：明确说明是否触动 §83–§94 任一冻结决议；若触动，需给出迁移路径与向后兼容分析；
4. **实现可行性**：给出落地位置（§X / 编译器 Phase）与最小实现路径。

## 5. 与规范的关系

- **Accepted 未 Implemented** 的 RFC 记录规范意图，但不改变 `docs/AILANG.md` 正文；正文仍为单一权威。
- **Implemented** 的 RFC 内容合并进 `docs/AILANG.md` 对应章节，并在附录 A 登记演进记录。
- 规范 §1.5.2 的 normative / informative 分区适用于已 Implemented 的 RFC 条款。

## 6. 规范解冻通道

对冻结规范（v0.2.1）的直接修改（非 RFC 通道）**应**满足下列其一：

- 经一份 **Accepted** RFC 授权；或
- 属 P0-0 类**治理地基补齐**（不改动语义决断、不新增关键字 / 文法产生式），并显式登记于附录 A、版本号维持不变。

2026-07-27 的 §1.5 + 附录 D + 本文档引入即依第二项执行（见附录 A「v0.2.1 治理地基补齐」记录）。
